# HoYoShade Hub 1.4.6

> GitHub Release 正文底稿。范围：1.4.5.5 之后至 2026-10-15 当前工作树中的启动器、插件管理、覆盖包、注入链和构建维护变更。
> GitHub 仅发布普通 x64 便携包；带 HoYoShade 框架的 `*_Full.zip` 只保留本地，不作为 Release 资产上传。

## 注入链与游戏启动

- 官方 XXMI、XXMI 手动模式和 Rocket 模式统一维护 Bridge / 额外模块 / OptiScaler 的有序注入链。
- 取消 Rocket、模块或自动动作时回收旧链清单和残留 DLL，保持幂等，避免旧配置继续注入。
- Rocket 模式扩展到原神、崩铁、绝区零、鸣潮和终末地等支持 XXMI 且具备 Rocket 后端的游戏；非原神按游戏插件 DLL 列表顺序加载。
- 注入模式允许 XXMI 手动模式共存；官方 XXMI 模式与 Hub 管线冲突时给出明确提示。
- 鸣潮改为识别真身 `Client-Win64-Shipping.exe`，支持本体目录 ReShade 安装、启用、停用和双 ReShade 检测。
- XXMI 实例查找增加后台执行、时间盒、缓存和负缓存，支持带版本后缀的实例目录；Mod 卡片读取自带 `preview.png`。

## 覆盖包与插件安装

- 修复本地覆盖包/扩展包被外层工作锁直接跳过的问题。
- 覆盖包解压、复制、版本归档移到后台执行，增加识别、解压、复制、归档和刷新阶段进度条。
- 修复 ZIP tar 兜底 stdout/stderr 顺序读取可能造成的等待；增加取消、路径穿越、临时文件清理和占用文件反馈。
- 覆盖包安装减少无关游戏缓存扫描和重复目录创建，保留一次性动作、同意记录和内容哈希保护。
- 扩展清单只认 ZIP 根目录或一层包装目录，避免误把 Streamline SDK 内部 `manifest.json` 当成扩展包。
- 插件页刷新、异步请求、页面卸载和旧结果发布增加生命周期与最新请求保护。

## OptiScaler、模块与配置

- 模块目录和远端组件条件继续去代码化，支持用户级模块配置、历史 DLL 别名、版本归档和覆盖包落位。
- OptiScaler 配置/迁移、构建选择、profile 完整性、DLSS-G、Streamline 和插件状态检查继续统一到启动管线。
- 增加下载续传、安装事务、CAS/硬链接安全、失败回滚和本地包路径校验。
- 更新、便携目录、后台任务和设置状态增加稳定性保护，避免旧请求覆盖新页面状态。

## ReShade 与界面

- 完善 ReShade 注入部署、AddonPath、游戏 ReShade.ini / ReShade2.ini 引导和原版 ReShade 管理。
- 插件管理页、OptiScaler 页、模块页、设置页和游戏启动页补充状态、进度、错误原因及刷新保护。
- 覆盖包、Mod、Rocket、XXMI 等入口保留一次性动作约束：页面刷新不会自动重复执行，内容变化需重新确认。

## 构建与验证

- 完整包构建默认清理未启用的搞怪滤镜，保留预设启用项、include 依赖和共享材质；`-KeepNoveltyShaders` 可关闭清理。
- 1.4.6 普通包不上传 `HoYoShadeHub_Portable_1.4.6_x64_Full.zip`；Full 包只作为本地测试/分发产物保存。
- 覆盖包安装、一次性动作、启动器回归和 UI 生命周期测试均纳入本轮验证。

## 已知边界

- 本版编译和离线回归不等于所有游戏实测；不同游戏的注入链、XXMI、Rocket 和 ReShade 兼容性仍需按游戏单独验收。
- Full 包中的 HoYoShade 框架与滤镜材质不作为 GitHub Release 资产上传。
